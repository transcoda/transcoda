# Decisions: M2 phase A: the workflow editor

Part of the decision log: history, not the current rules. Today's rules are in [`docs/dev/`](../dev/); the index of every entry is in [README.md](README.md).

## 2026-10-16 M2 Task 1: web test setup, node-catalogue fixture, data hooks

- **jsdom node measurement (builder's call):** React Flow 12 measures nodes with `offsetWidth`/`offsetHeight`, not with the ResizeObserver entry, and jsdom has no layout (always 0), so the planned polyfills alone made nodes visible (via `initialWidth`/`initialHeight`) but never stored handle bounds, and no edge rendered. `apps/web/src/test/setup.ts` therefore also gives elements with the class `react-flow__node` an `offsetWidth`/`offsetHeight` of their inline style size (groups) or the card size 210 × 120; every other element keeps jsdom's 0. `apps/web/src/test/flow.test.tsx` pins that a node and an edge render.
- **Fixture JSON in the web project:** `apps/web/tsconfig.json` includes `src/test/fixtures/*.json`, because a composite project must list every file it imports (`import raw from './nodes.json'`, TS6307 otherwise).
- **`useCatalog` cache:** one module-level `nodes.list` promise shared by every consumer, failures included; `reload()` drops it and notifies every mounted consumer, which refetch once together.
- **`describeError` fallbacks:** an error that is neither an `ORPCError` nor a `TypeError` maps to `{ code: null, status: null }` with its own message (or "Something went wrong"); an undefined 400 keeps its oRPC code with the message "The server rejected the request".

## 2026-10-16 M2 Task 2: dialog, toast, chip primitives and shared time formatting

- **Undrawn icons (builder's call):** `alert`, `chevron-down`, `trash` and `play` are copied from the handoff screens; `info`, `check-circle`, `x-circle`, `subworkflow`, `chevron-right`, `history`, `search`, `pencil` and `pause` are not drawn there and follow the same 24-unit stroke style. `workflow` reuses the `workflows` nav glyph.
- **Toast regions:** the polite `role="status"` region is always mounted (so info toasts are announced); the `role="alert"` region is mounted only while an error toast exists, since an alert is announced when it is inserted. Using an error toast's action also dismisses it.
- **Dialog close path:** Escape (keydown) and the browser's own `cancel` request both call `onClose` and are otherwise prevented, so the parent's `open` prop stays the only source of truth.
- **`fmtAgoLong` past a day:** "saved " plus day and short month in the browser's locale (`Intl.DateTimeFormat(undefined, …)`, "12 Oct" in en-GB, "Oct 12" in en-US), like the other dates in the app. `fmtDayMonth` (the tokens page's "REVOKED 12 OCT" formatter) moved to `lib/time.ts` with `fmtDate`/`fmtAgo`.
- **New non-token color:** `--backdrop` (`rgb(0 0 0 / 0.6)`) for the dialog backdrop, at the top of `styles.css`.

## 2026-10-16 M2 Task 3: workflow list, create, rename and delete pages

- **Errors inside dialogs are inline; danger dialogs focus Cancel (controller ruling):** toasts are inert while a modal `<dialog>` is open, so a failure from an action taken inside a dialog is shown in the dialog body (`role="alert"` with the `describeError` text and "Try again"), never as a toast. `Dialog` gives initial focus to the child marked `data-autofocus` (an override); otherwise a `tone="danger"` dialog focuses its footer button labeled "Cancel" (or the dialog itself, never the destructive action) and other dialogs the first focusable child. (Fix round: danger dialogs no longer need the marker.)
- **Dialog focus return (fix-round ruling):** `Dialog` takes `returnFocusTo` (an element or a ref). On close focus goes there when it is still in the document, else to the element focused at open. A dialog opened from a menu item passes the menu button, because the item has unmounted by then; the delete dialog returns focus to the row's "Actions for <name>" button. When the deleted row itself is gone, focus is left to the browser.
- **List page layout (builder's call, undrawn):** *(Superseded 2026-10-18 by the owner: the "New sub-workflow" button is gone; "New workflow" leads to the page where the kind is chosen.)* `.page` with a `.page-head` row (h1 "Workflows", "New workflow" primary, "New sub-workflow" secondary) and a rounded `.wf-table` panel in the tokens-table style; the empty state (screen 02's copy and chain) sits in a bordered panel below the head instead of over a canvas. A sub-workflow with no users shows "Used by 0" (the brief's rule, no special case).
- **"Add a trigger" before Task 16:** creates a workflow named "Untitled workflow" (screen 02's page title) and opens it; the example button is disabled with the title "arrives in Task 16".
- **Row menu and inline rename:** a menu button ("Actions for <name>", three-dot icon `more`, drawn in the same stroke style) opens a `role="menu"` with "Rename" / "Delete"; Escape or a click outside closes it. Rename: Enter saves (trimmed), Escape cancels, blur also cancels (nothing is saved without Enter); an empty or unchanged name just closes the editor; a failure is an error toast (the rename is not inside a dialog), the editor stays open and gets focus back once it is enabled again. An edit ended by Enter or Escape returns focus to the row's actions button; one ended by blur leaves focus where the user moved it.
- **Delete:** the `IN_USE` replacement text is `role="alert"` so it is announced; the Delete button stays disabled (retrying would fail the same way); success closes the dialog, reloads and shows the info toast "Deleted <name>". The destructive button is a new `.btn-danger` (filled `--st-failed` on `--st-failed-ink`).
- **New page:** *(Superseded by Activation, 2026-10-17: the note says "until you activate a version", not "enable".)* h1 follows the chosen kind ("New workflow" / "New sub-workflow"), with screen 02's note "New workflows never touch files until you enable them."; an empty name shows the alert "Enter a name", a failed create "Could not create the workflow, try again" and keeps the form.
- **Table width:** the list table's minimum width (720 px) fits the 1024 px desktop beside the nav, so the row menu is never clipped there; below 1024 px the table scrolls horizontally inside its panel. **Known limitation (desktop-first):** there the scroll container can clip the open row menu; a portal/popover menu would fix it if the list ever needs a narrow layout. Button-styled links (`a.btn`) keep their button colors and drop the link underline.
- **Status fallback (fix round):** a workflow with `valid: false` and `errorCount: 0` shows an error chip "Invalid", so an invalid row never shows no status. A load error is shown whenever `useWorkflows` reports one (with "Try again").
- **Settings nav tag:** "later" instead of "M2" (Settings is not in M2's scope); the screen-reader text reads "Settings, coming later" ("…, coming in M2" for dated items).

## 2026-10-16 M2 Task 4: editor model (graph operations, connection rules)

- **Undrawn refusal copy (builder's call):** besides the plan's refusals, operations on a node or group that is gone refuse with "That node no longer exists" / "That group no longer exists"; a port id the node's definition does not have refuses with "That port does not exist"; `createGroup` with no existing node refuses with "Select at least one node to group"; `setPinnedVersion`/`setOverride` on a node that is not `core:run-subworkflow` refuse with "That node does not run a sub-workflow". The edge and group caps reuse the server's wording ("A workflow can have at most 2000 edges" / "… 100 groups").
- **`compatibleTargets` and sub-workflow start/end (builder's call):** in a sub-workflow trigger and finish nodes are excluded and `core:subworkflow-end` stays (it has a file input, and the palette offers "End"); in a main workflow the `subworkflow-io` nodes are excluded. Unavailable nodes are kept so the palette can list them disabled with the reason.
- **Connection check order:** self-loop, then the output and input exist, then the port types match, then the input is free; the edge cap is checked by `connect` after the rules. Ports are looked up on the right side only (`from` among outputs, `to` among inputs).
- **Run-node settings that are not an object** (e.g. `null`) are treated as `{}` by `setPinnedVersion`/`setOverride`, so those operations always leave an object with an `overrides` object.
- **Fixture names:** `otterFinchSub()` in `apps/web/src/test/fixtures/graphs.ts` is the server's `languageCleanupSub()` written out literally; `otterFinchMain` omits the server fixture's `extraNodes` option.
- **Placement rules (review fix):** `placementRefusal(def, graph, catalog)` is shared by `addNode` and `duplicateNode` and mirrors the server's TRIGGER_COUNT / SUBWORKFLOW_IO_COUNT / NODE_NOT_ALLOWED_HERE: "A workflow has exactly one trigger" (a second trigger in a workflow), "A sub-workflow has exactly one start" (a second start), "<title> is not allowed in a workflow" (Start/End in a workflow) and "<title> is not allowed in a sub-workflow" (trigger or finish in a sub-workflow), the last two in the server's wording; a second End is allowed. The graph's own `kind` is the workflow kind and the catalog gives the kinds of the nodes already placed, so the signature is `(def, graph, catalog)` rather than the review's `(kind, def, graph)`. `duplicateNode` therefore takes the catalog (`duplicateNode(g, id, catalog)`) and refuses a node of an unknown type with "Unknown node type <type>".
- **Other review-fix refusals:** `addNode` with an `id` already in the graph: "A node with the id <id> already exists"; `setLabel` past 120 characters (`MAX_LABEL_LENGTH`, the schema's `max(120)`): "A label can be at most 120 characters"; `setPinnedVersion` with a non-integer or a value below 1: "The pinned version must be a whole number of at least 1".

## 2026-10-16 M2 Task 5: editor state, issue mapping, graph equality, undo history

- **Node state precedence (builder's call):** among a node's issues the one with the strongest border wins the badge and word (red > amber > dashed), errors before warnings at the same level, and the first in server order on a tie; issues that draw nothing (`NODE_UNREACHABLE`, `OVERRIDE_DROPPED`, `NO_WRITE_PATH`, a warning `NODE_OUTDATED`) never take the word. `dim` is the strongest dim of any issue (0.6 over 0.7), independent of the winning border, so an unavailable node with a settings problem is amber and dimmed. `SUBWORKFLOW_OUTDATED` sets the badge `outdated-pin` only when nothing with a border is present.
- **Unknown codes and known codes outside the table:** an error is `generic-error` "error" with a red border, a warning is `generic-warning` "warning" with an amber border (the word keeps color from carrying meaning alone). Codes the server sends with a `nodeId` but the N6 table does not list (`GRAPH_CYCLE` on the cycle's first node, `INPUT_MULTIPLE_EDGES` on the target node, `GROUP_MISSING`) render the same way.
- **`fieldIssues`** holds only `INVALID_SETTINGS` issues with a `settingPath` (Run-node `INVALID_OVERRIDE` issues stay in `issues` for Task 15).
- **Broken edges:** `edgeStateFor(edgeId, issues, intoBroken?)` takes the set from `edgesIntoBroken(graph, states)` (edge ids whose target node has a red border, `states` being the per-node `NodeState` map), so the caller computes node states once.
- **Equality:** `stableStringify` is the server's copy except that it skips `undefined` object values (in-memory drafts may carry them; the wire drops them). `isLayoutOnlyChange` compares `bypassed ?? false`, ignores edge ids (endpoint multiset, as the server's `edgeKeys`) and node/edge order, and is true for two equal graphs.
- **Reducer details:** `EditorState` gains `coalesceKey` (`<coalesce>:<key>` of the last apply); a run of same-key applies shares one undo step and any select, undo, redo or save ends it. An apply whose graph equals the draft is a no-op (no empty undo step). `apply`, `undo` and `redo` do nothing while `readOnly`. Undo/redo drop selected ids that no longer exist. `saved` also updates `workflow.currentVersion`, `valid` and `errorCount` from the response issues; `rebase` updates `currentVersion`.

## 2026-10-16 M2 Task 6: React Flow adapter (`toFlow` / `fromFlow`)

- **Collapsed groups:** a member of a collapsed group is `hidden`; an edge with one end hidden is re-targeted to the group node with the handle id `'group'` (`GROUP_HANDLE`); an edge with both ends inside the same collapsed group is `hidden`. Edge ids never change. A node whose `groupId` names no group (`GROUP_MISSING`) has no parent and keeps its absolute position. The `trace` parameter is accepted but unused until Task 23.
- **Position mapping (builder's call):** only `position` changes with `dragging !== true` become graph moves — a finished drag and an arrow-key nudge (`dragging: false`) and the resizer's own position changes (no `dragging` key); positions while a drag is in progress map to nothing, so the canvas (Task 10) shows the live drag itself. Each batch yields one move op coalesced as `move` (the page supplies the key).
- **Leaving a group:** a child dropped (`dragging: false`) with its card center (measured size, else `NODE_SIZE`) outside its group's box is ungrouped at its absolute position. Resizing never ungroups, even when the box shrinks past a member. Nothing groups a node by dropping it into a group (YAGNI; grouping is the explicit "Group" action).
- **Group drag and resize:** a dragged group moves its members by the same delta (the graph stores them absolute); a resize (`dimensions` with a boolean `resizing`) sets position and size via `resizeGroup`, and the members keep their absolute positions because React Flow compensates their relative positions in the same batch. Measurement-only `dimensions` changes (no `resizing`) map to nothing.
- **Removal:** removed groups are ungrouped (members stay) and removed nodes go through `removeNodes` in one op, so a refusal (a sub-workflow's start or end) is returned as a refusal. React Flow's own delete also cascades to a removed group's children and their edges; since Task 11 React Flow never deletes (no `deleteKeyCode`, no `deleteElements` call, no `onBeforeDelete`) — deletion is `removeSelection` from the keyboard and `removeNodes` from the toolbar.
- **Selection:** a `select` result is the complete next selection of the kind that changed — `fromNodeChanges` gives `nodes` and `group` (one group at a time: the one just selected, else the first still selected) with `edges: []`, `fromEdgeChanges` gives `edges` with `nodes: []`. React Flow reports both kinds in two calls of the same tick, so the page merges each result by kind against the latest state. `fromEdgeChanges` takes an optional second argument, the flow edges from `toFlow`, so an added edge keeps the ones already selected (the plan's signature had only `changes`).
- **Result shape:** results are aggregated per batch (geometry op, removal op, selection) and ignored changes are omitted rather than returned as `null`.
- **Review fixes:** the `saved` action carries the graph that was sent (`graph`); `saved` becomes that graph and `dirty` is `!graphEquals(draft, graph)`, so an edit made while the save was in flight stays unsaved. `editorReducer(s: EditorState | null, a)` returns a null state unchanged for every action except `loaded`, so it goes straight into `useReducer(editorReducer, initialEditorState())`. A `validating` with a seq lower than the latest is ignored, like a stale `validated`. On the drag path an apply that returns the draft itself is a no-op before any comparison, and `graphEquals` memoises each graph's serialization in a `WeakMap` by reference (drafts are immutable values), so an apply serializes only the new graph once for both the no-op check and the dirty flag.

The reason is the item's accessible description (`aria-describedby`), the name stays the title. Precedence: read-only disables everything; an unavailable node shows its `availability.reason`; in a sub-workflow, trigger and finish nodes show "main workflow only".
- **Plugin mark:** plugin nodes show the plug icon after the title (screen 05) and their accessible name is "<title>, plugin".

## 2026-10-16 M2 Task 10: editor page, live validation, save and conflicts

- **Page shape:** `/workflows/:id` renders inside the Shell (side nav stays) as `.editor`: the header row, then palette 240 px | canvas | inspector column 340 px ("Select a node" until Task 13). The Shell is held to the window height while the editor is mounted (`.shell:has(.editor)`), so the canvas fills the rest. `EditorPage` keys a fresh `ReactFlowProvider` + editor by `id@version`, so another workflow or version starts with a fresh state, history and viewport.
- **Editable:** the canvas is editable when the workflow is the current version (no `?version=N`) and the node catalog has loaded; otherwise palette, toolbar, connections, deletion and Save are off (`EditorActions.readOnly`). `?version=N` loads that version read-only with no banner yet (Task 18). Group collapse on a read-only canvas is view-only (`withViewCollapse` over a local map); on an editable one it is a graph op.
- **Live validation:** `useValidation` sends `workflows.validate({ graph, id })` 400 ms after the last edit, one request in flight; an edit made meanwhile is sent when it returns. A response for a draft that has since changed is dropped; a failed call keeps the issues (new reducer action `validateFailed` clears `validating`). The draft that arrives with the load is not validated (its issues came with it).
- **Save:** exactly `{ id, baseVersion, graph }` (the note waits for Task 18's contract change; the header's "Save with a note…" menu exists behind `noteMenu`, off). Success → `saved` with the sent graph, `updatedAt` set to now for the pill, toast "Saved vN". `VERSION_CONFLICT` → `ConflictDialog` (Escape closes it and keeps the draft; "Reload the latest version" re-runs the load; "Save over it" → `rebase` then save with `baseVersion = currentVersion`). Any other failure → error toast `describeError(e).message` with "Try again"; draft and dirty flag untouched. `ConflictDialog` takes an extra `onClose` (Dialog needs one).
- **Header:** pill "vN · saved 2 min ago" / "vN · unsaved changes" (re-rendered every 30 s); it is a button for the versions panel (Task 18). The name is a button (title "Rename") that becomes an inline input (Enter/blur saves through `workflows.rename`, Escape cancels; disabled when read-only). "Try on a file" disabled with title "needs the engine". Save reads "Save v<savedVersion + 1>", primary when dirty and editable. The header buttons are drawn 40 px (screen 05) and the pill 32 px, each with a `::before` hit area of 44 px.
- **Adding nodes:** palette click adds at the canvas center, a drop at the drop point (card header under the pointer); a spot already taken moves the new card right by card width + 70 px until it is free. A sub-workflow item adds a Run node pinned to that sub-workflow's current version with empty overrides (the plan puts this in Task 15; added here so the item is never a silent no-op). "+" on an output opens the node search ("Drop on a file input" / "Drop on a data input"); the picked node is placed right of the origin and connected to its first input of that port type in one undo step. Every refusal (placement, caps, start/end rules) is an error toast.
- **Connections:** `isValidConnection` is `checkConnection`; a connection released on (or clicked onto) a port that does not fit shows the reason as a toast via `onConnectEnd` / `onClickConnectEnd`. During a drag, `TcHandle` marks ports `is-compatible` / `is-incompatible` from React Flow's `useConnection` (checked in the browser).
- **Canvas state:** React Flow nodes are derived from the draft; a drag moves a local overlay (`applyNodeChanges`) and only the drop dispatches the move (coalesced per drag). Measurements carry over to newly derived nodes so cards are not re-measured on every edit. Dropped positions and resized group sizes are rounded to whole pixels (`fromFlow`). Selection results are merged by kind against the latest sent selection. Deleting a group ungroups it (its unselected members and their edges stay); a deletion the graph refuses (last Start/End of a sub-workflow) changes nothing and shows a toast. (Superseded in Task 11: Delete/Backspace go through `useEditorKeys` → `removeSelection`; React Flow's delete and `onBeforeDelete` are gone.)
- **Viewport:** `minZoom` 0.1 so the icon zoom level is reachable; a non-empty graph is fitted on load at most at 100 %; an empty one starts at 100 %. Controls sit bottom-right with the minimap stacked above them.
- **Toolbar keyboard path (N8):** Enter or "." on a focused node selects it and moves focus to its toolbar's first enabled button; Escape in the toolbar returns focus to the node (since Task 11 the node stays selected: the toolbar is `nokey` and stops Escape). `TcToolbar` carries `data-node-id`.
- **Groups from a selection:** `createGroup` takes optional measured card sizes (React Flow's `measured`), falling back to `NODE_SIZE`, so tall cards do not cover the group header.

## 2026-10-16 M2 Task 11: issues panel, canvas banner, keyboard path, viewport, narrow and catalog-less states

- **Issues panel:** a `<details>` (open by default) at the bottom of the inspector column; summary "N errors · M warnings", "1 error", "No issues". Entries are errors first, then warnings (server order within each); each is a button: icon + a visually hidden "Error"/"Warning", the node title (label, else catalog title, else the type; an unknown id shows the id), "Edge" or "Workflow", and the server's message. Clicking selects and centers: a node (or its collapsed group) is centered at most at 100 % with 40 % padding, an edge by its two ends, a workflow entry fits the whole graph; with `settingPath` it goes through `EditorActions.focusField` (Task 13 focuses the field). The centring computes the viewport directly (`getNodesBounds` + `getViewportForBounds` + `setViewport`) because React Flow 12's `fitView` is queued until the next node update.
- **Canvas banners:** *(Superseded by Activation, 2026-10-17: no "Can't enable" or review banner; the can't-run banner and the info banner of the save's changes replace them.)* a stack at the top of the canvas (`role="status"` each): the narrow notice, the catalog notice, then `CanvasBanner`'s "Can't enable: <first error message>. Dry runs still work." (one trailing full stop of the message is dropped so the sentence reads once) and the review banner "<reviewNote> — Review, then enable to clear this."
